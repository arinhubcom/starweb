# I18N

Public site languages. App pages and islands → [SAAS](SAAS.md). EmDash content → [CMS](CMS.md). UI text → [WRITING](WRITING.md).

## Routing

### [Astro](STACK.md#astro) i18n

- `i18n` in `astro.config`: `locales`, `defaultLocale`, `fallback` if a locale can lack pages (else 404).
- Locale codes lowercase with hyphens (`en`, `pt-br`); `src/pages/` folders named exactly like `locales` entries.
- `routing.prefixDefaultLocale: false` unless the task needs `/en/` (then default pages go in `src/pages/en/`).
- `routing.fallbackType: "rewrite"` to serve the fallback at the requested URL (default `"redirect"`; a rewrite returns `302` with the fallback body).
- No `routing: "manual"`, `i18n.domains`, or custom locale `path` objects unless the task needs them (`domains` needs the Node.js/Vercel adapter; custom paths need `output: "server"` with no prerendered pages).
- Current locale: `Astro.currentLocale` (falls back to `defaultLocale` without a prefix).
- `astro:i18n`: every internal link via `getRelativeLocaleUrl(locale, path)`, never a hand-written `/${locale}/...`. A locale not in `locales` throws.
- `site` in `astro.config`, or `getAbsoluteLocaleUrl()` / `getAbsoluteLocaleUrlList()` return relative URLs.
- Language switcher: `getRelativeLocaleUrl()` per `locales` entry; for EmDash content, `getTranslations()`.

## SEO

### [Google Search Central](STACK.md#google-search-central) hreflang

- `<link rel="alternate" hreflang href>` in `<head>` for every version, including the page itself; same set on every version.
- Absolute `https://` URLs. ISO 639-1 language, optional ISO 3166-1 alpha 2 region (`pt-BR`); never a region alone.
- One `hreflang="x-default"`.
- Custom pages: add the links yourself (`getAbsoluteLocaleUrl()` per locale + `x-default`); `<EmDashHead>` emits `hreflang` only for content entries.
- Emit from `<head>` only. No `i18n` in `sitemap()` options; leave EmDash collection sitemaps (they add `xhtml:link` alternates).

### [MDN](STACK.md#mdn) `lang`

- Base layout: `<html lang={Astro.currentLocale}>` (replace the starter's hard-coded `lang="en"` in `Base.astro`).
- Other-language text: `lang` on its element, valid BCP 47 tag.

## Content

### [EmDash](STACK.md#emdash) i18n

- Same Astro `i18n` block turns on translation; without it EmDash is single-language.
- Pass `locale` to `getEmDashCollection(collection, { locale })`, `getEmDashEntry(collection, slug, { locale })`, `getMenu(name, { locale })`, `getTaxonomyTerms(taxonomy, { locale })`; default otherwise.
- `entry.data.slug` (no locale prefix) for route segments; `entry.data.id` for `getTranslations()` and `getEntryTerms()`.
- Fallback chain (requested, `fallback`, default) applies to single-entry queries only; list queries return the requested locale only.
- Keep the same slug across translations that rely on the fallback chain.
- Different slugs: `getTranslations(collection, id)`; filter out drafts and scheduled entries before a public switcher.
- `<EmDashHead>` in the base layout. `getHreflangAlternates(collection, id, { siteUrl })` needs an absolute `siteUrl` or returns `[]`.
- `translatable: false` on fields identical in all locales (price, image); copied on publish.
- Create translations: PolyStella panel (AI, below), admin **Translate**, or `emdash content create <collection> --locale <code> --translation-of <id> --draft`.
- EmDash collections: its locale-aware `/sitemap-{collection}.xml`.
- No translating the EmDash admin UI in site code ([Translating EmDash](https://docs.emdashcms.com/contributing/translating/)).

### [PolyStella](STACK.md#polystella) content translation

- AI translation of EmDash content: `npm i @cloudflare/polystella-emdash`; `emdash({ plugins: [polystellaEmdash(options)] })` (native plugin). Peers come with EmDash.
- No `@cloudflare/polystella-astro` (translates repository files at build time, own routes) → EmDash content, Astro i18n routing.
- No `polystellaEmdashAstro()` (`Astro.locals.t`, `lhref`, catalog overrides) → Paraglide JS (UI strings, below).
- `catalogs` is required: `defaultLocale` plus one `locales` entry per Astro `locales` code, each `{ dictionary: {}, filePath: "polystella/<locale>.json" }` (no file needed). Leave the **Catalog** tab and overrides unused.
- `provider: { kind: "workers-ai-binding", binding: "AI" }`; `"ai": { "binding": "AI" }` in `wrangler.jsonc` → [DEPLOY](DEPLOY.md). Workers AI bills the account also in `astro dev`.
- `models.allowed` (non-empty) and `models.defaults.default` (in `allowed`): a Workers AI text model, for example `@cf/zai-org/glm-4.7-flash`.
- An administrator enables collections and fields in **PolyStella** → **Collections**; nothing is on by default. Translates `string`, `text`, and Portable Text fields.
- The panel creates or updates a translation draft (`translationOf`) and never publishes; review, then publish.
- Glossary optional: `glossaryDefaults: await loadGlossaryDefaults({ locales, file: "./src/i18n/glossary/{locale}.yaml", projectRoot: new URL(".", import.meta.url) })` from `@cloudflare/polystella-emdash/config`.

## UI strings

### [Paraglide JS](STACK.md#paraglide-js)

- Also for the site; one catalog shared with the app → [SAAS](SAAS.md).
- No PolyStella for UI strings: no `Astro.locals.t`, no `polystella translate-ui` on `messages/` (it protects only `{{name}}`, not `{name}`, and translates `$schema`).
- `messages/{locale}.json`: flat keys, `{name}` placeholders; call `m.key({ name })` from `src/paraglide/messages.js`.
- `project.inlang/settings.json`: `baseLocale` and `locales` equal `defaultLocale` and `locales` in `astro.config`.
- `vite.plugins`: `paraglideVitePlugin({ project: "./project.inlang", outdir: "./src/paraglide", emitTsDeclarations: true, strategy: ["url", "globalVariable", "baseLocale"] })`. `globalVariable` before `baseLocale` (prerendered pages need it); inside `paraglideMiddleware()` `getLocale()` reads AsyncLocalStorage first.
- `src/middleware.ts` branches on `context.isPrerendered`.
  - On-demand: `paraglideMiddleware(context.request, () => next())` from `src/paraglide/server.js`. Never pass the callback's `request` to `next()` (prefix stripped; Astro rewrites `/de/about` to `/about`, skips `src/pages/de/`). Never `setLocale()` (shared global across concurrent requests in an isolate → wrong locale) → [ARCH](ARCH.md).
  - Prerendered: no `paraglideMiddleware()`; `setLocale(assertIsLocale(context.currentLocale ?? baseLocale))` from `src/paraglide/runtime.js`, then `return next()`.
- No `disableAsyncLocalStorage` (Workers support `node:async_hooks`; Node.js APIs on by default with `compatibility_date` ≥ `2026-08-04`) → [ARCH](ARCH.md).
- No server `overwriteGetLocale()` without per-request locale storage.
- Source messages in English → [WRITING](WRITING.md); translation files are the only non-English files.

## Formatting

### [MDN](STACK.md#mdn) `Intl`

- Dates: `new Intl.DateTimeFormat(locale, { dateStyle, timeZone })`; no hand-built strings. Always pass `locale` (`Astro.currentLocale`) and `timeZone`. Ranges: `formatRange()`.
- Numbers: `new Intl.NumberFormat(locale, options)`; no `toFixed()` or manual separators. `style: "currency"` needs `currency`; `style: "unit"` needs `unit` (else `TypeError`). `notation: "compact"` for `1.2M`.

## Direction

- Add an RTL locale only when the task needs it: `<html lang={Astro.currentLocale} dir={getTextDirection()}>`, `getTextDirection()` from `src/paraglide/runtime.js`.
- `dir` on `<html>`, no CSS `direction`. `dir="auto"` on unknown-direction user text; `<bdi>` inline.
- [Tailwind CSS](STACK.md#tailwind-css) logical utilities (`ps-*`, `pe-*`, `ms-*`, `me-*`), never `pl-*`/`pr-*`/`ml-*`/`mr-*` for reading-direction spacing; `rtl:` variant for other direction styles.
