# I18N

Rules for languages on the site (public pages). For app pages and islands, follow [SAAS.md](SAAS.md). For content in EmDash, also follow [CMS.md](CMS.md). For UI text, follow [WRITING.md](WRITING.md).

## Routing

### [Astro i18n routing](https://docs.astro.build/en/guides/internationalization/)

- Set `i18n` in `astro.config` with `locales`, `defaultLocale`, and, if a locale can lack pages, `fallback`. Without `fallback`, a missing translated page returns 404.
- Write each locale as a lowercase code with hyphens, for example `en` or `pt-br`. Name each folder in `src/pages/` exactly like its entry in `locales`.
- Keep `routing.prefixDefaultLocale` at `false`. EmDash does not support `true`: `/_emdash/admin` returns 404. For `/en/` URLs, add a redirect or rewrite in front of the site.
- Use `routing.fallbackType: "rewrite"` to show the fallback page at the requested URL. The default is `"redirect"`.
- Do not use `routing: "manual"`, `i18n.domains`, or custom locale `path` objects, unless the task needs them. `domains` needs the Node.js or Vercel adapter, and custom paths need `output: "server"` with no prerendered pages.
- Read the current locale from `Astro.currentLocale`. It falls back to `defaultLocale` when the URL has no prefix.

### [astro:i18n](https://docs.astro.build/en/reference/modules/astro-i18n/)

- Build every internal link with `getRelativeLocaleUrl(locale, path)`. Do not write `/${locale}/...` by hand.
- Set `site` in `astro.config`. `getAbsoluteLocaleUrl()` and `getAbsoluteLocaleUrlList()` return relative URLs without it.
- Build a language switcher with `getRelativeLocaleUrl()` for each entry of `locales`. For EmDash content, build it from `getTranslations()` (see EmDash below).
- Do not pass a locale that is not in `locales`. `getRelativeLocaleUrl()` throws an error.

## SEO

### [Localized versions (hreflang)](https://developers.google.com/search/docs/specialty/international/localized-versions)

- Add `<link rel="alternate" hreflang="..." href="...">` to `<head>` for every version, including the page itself. Use the same set on every version. Without the links on all versions, Google ignores them.
- Use absolute URLs with `https://` in `href`.
- Use a language code (ISO 639-1), optionally with a region code (ISO 3166-1 alpha 2), for example `en` or `pt-BR`. Do not use a region code alone.
- Add one `hreflang="x-default"` link that points to the version for users with no matching language.
- Emit the links from `<head>` only. Do not set `i18n` in the `sitemap()` options. EmDash collection sitemaps add `xhtml:link` alternates from the same translations, so leave them as they are.

### [HTML lang attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/lang)

- Set `<html lang={Astro.currentLocale}>` in the base layout. Do not hard-code `lang="en"`.
- Mark text in another language with `lang` on its element, for example `<span lang="fr">`. The `lang` value must be a valid [BCP 47](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/lang) tag.

## Content

### [EmDash i18n](https://docs.emdashcms.com/guides/internationalization/)

- Turn on content translation with the same Astro `i18n` block. Without it, EmDash is single-language.
- Pass `locale` to `getEmDashCollection(collection, { locale })`, `getEmDashEntry(collection, slug, { locale })`, `getMenu(name, { locale })`, and `getTaxonomyTerms(taxonomy, { locale })`. Without it, EmDash uses the default locale.
- Use `entry.data.slug` (the slug without the locale prefix) when a route adds the locale segment. Use `entry.data.id` for `getTranslations()` and `getEntryTerms()`.
- Expect the fallback chain (requested locale, `fallback` locale, default locale) only in single-entry queries. List queries return only the requested locale.
- Keep the same slug in all translations that rely on the fallback chain. A request for a slug that exists only in another locale finds no entry.
- Link translations with different slugs with `getTranslations(collection, id)`. Remove drafts and scheduled entries before you render a public language switcher: the function returns them.
- Add `<EmDashHead>` to the base layout. It emits `hreflang` links for EmDash content when i18n is on. For `getHreflangAlternates(collection, id, { siteUrl })`, pass an absolute `siteUrl`, or it returns an empty array.
- Set `translatable: false` on a field that must be the same in all locales, for example a price or an image. EmDash copies it to all translations when you publish.
- Create translations in the admin UI with **Translate**, or with `emdash content create <collection> --locale <code> --translation-of <id> --draft`.
- Use the locale-aware `/sitemap-{collection}.xml` from EmDash for EmDash collections.
- Do not translate the EmDash admin UI in the site code. It has its own catalogs (see [Translating EmDash](https://docs.emdashcms.com/contributing/translating/)).

## UI strings

### [Paraglide JS](https://paraglidejs.com/astro)

- Use Paraglide JS for UI strings on the site too, so the site and the app share one message catalog. Follow the app rules in [SAAS.md](SAAS.md).
- Put messages in `messages/{locale}.json`, with flat keys and `{name}` placeholders. Call them as `m.key({ name })` from `src/paraglide/messages.js`.
- Set `baseLocale` and `locales` in `project.inlang/settings.json` to the same values as `defaultLocale` and `locales` in `astro.config`.
- Add `paraglideVitePlugin({ project: "./project.inlang", outdir: "./src/paraglide", emitTsDeclarations: true, strategy: ["url", "globalVariable", "baseLocale"] })` to `vite.plugins`. Keep `globalVariable` before `baseLocale`: prerendered pages need it. Inside `paraglideMiddleware()`, `getLocale()` reads the request locale from AsyncLocalStorage first, so on-demand pages do not use the global variable.
- Branch on `context.isPrerendered` in `src/middleware.ts`. Never call `setLocale()` for an on-demand page: it writes a global variable that concurrent requests in one isolate share, and a request can render in the locale of another request (see [ARCH.md](ARCH.md)).
- Do not use `paraglideMiddleware()` for prerendered pages. Call `setLocale(assertIsLocale(context.currentLocale ?? baseLocale))` from `src/paraglide/runtime.js`, then `return next()`.
- Wrap the request of an on-demand page with `paraglideMiddleware(context.request, () => next())` from `src/paraglide/server.js`. Do not pass the `request` argument of the callback to `next()`: Paraglide removes the locale prefix from it, and Astro would rewrite `/de/about` to `/about` and skip `src/pages/de/`.
- Do not set `disableAsyncLocalStorage`. Workers support AsyncLocalStorage from `node:async_hooks`, and with `compatibility_date` set to `2026-08-04` or later, Node.js APIs are on by default (see [ARCH.md](ARCH.md)).
- Do not use `overwriteGetLocale()` on the server unless you give each request its own locale storage. A shared variable has race conditions between concurrent requests.
- Write the source messages in English and follow [WRITING.md](WRITING.md). Translation files are the only files that hold other languages.

## Formatting

### [Intl](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl)

- Format dates with `new Intl.DateTimeFormat(locale, { dateStyle, timeZone })`. Do not build date strings by hand.
- Pass `locale` (from `Astro.currentLocale`) and `timeZone` every time. Without them, the output depends on the runtime.
- Format numbers with `new Intl.NumberFormat(locale, options)`. Do not use `toFixed()` or manual separators for display.
- Set `currency` with `style: "currency"`, and `unit` with `style: "unit"`. Without them, the constructor throws a `TypeError`.
- Use `notation: "compact"` for short counts such as `1.2M`.
- Use `Intl.DateTimeFormat.prototype.formatRange()` for date ranges.

## Direction

### [dir attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/dir)

- Add a right-to-left locale only when the task needs it. Then set `<html lang={Astro.currentLocale} dir={getTextDirection()}>`, with `getTextDirection()` from `src/paraglide/runtime.js`. `lang` does not set the direction.
- Use `dir` on `<html>`. Do not set the CSS `direction` property.
- Use `dir="auto"` on elements with user text of unknown direction. Use `<bdi>` for inline user text.
- Use logical Tailwind CSS utilities such as `ps-4`, `pe-4`, `ms-4`, and `me-4`. Do not use `pl-*`, `pr-*`, `ml-*`, and `mr-*` for spacing that follows the reading direction. Use the `rtl:` variant for other direction-specific styles.
