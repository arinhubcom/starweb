# I18N

This file covers the languages of the public site: routing, hreflang, content translation, UI strings, formatting, and text direction. Read it before you add a language.

- For app pages and islands, see [SAAS](SAAS.md).
- For EmDash content, see [CMS](CMS.md).
- For UI text, see [WRITING](WRITING.md).

## Set up routing

### Configure Astro i18n

- Add `i18n` to `astro.config` with [Astro](STACK.md#astro) `locales` and `defaultLocale`.
- If a locale can lack pages, add `fallback`. Otherwise Astro returns a 404.
- Write locale codes in lowercase with hyphens, such as `en` and `pt-br`.
- Name the `src/pages/` folders exactly like the `locales` entries.
- Set `routing.prefixDefaultLocale: false`, unless the task needs `/en/`. Then put the default pages in `src/pages/en/`.
- Set `routing.fallbackType: "rewrite"` to serve the fallback at the requested URL.
- The default is `"redirect"`. Astro returns `302` with the fallback body.
- Do not use `routing: "manual"`, `i18n.domains`, or custom locale `path` objects, unless the task needs them.
- `domains` needs the Node.js or Vercel adapter. Custom paths need `output: "server"` with no prerendered pages.

### Use the current locale

- Read the current locale from `Astro.currentLocale`. Without a prefix, it falls back to `defaultLocale`.
- Build every internal link with `getRelativeLocaleUrl(locale, path)` from `astro:i18n`.
- Never write `/${locale}/...` by hand. A locale that is not in `locales` throws an error.
- For the language switcher, call `getRelativeLocaleUrl()` for each `locales` entry.
- For EmDash content, use `getTranslations()` in the switcher.

## Tell search engines about each language

### Add hreflang links

- Follow [Google Search Central](STACK.md#google-search-central).
- Add `<link rel="alternate" hreflang href>` in `<head>` for every version, including the page itself.
- Use the same set of links on every version.
- Use absolute `https://` URLs.
- Use an ISO 639-1 language code and an optional ISO 3166-1 alpha 2 region, such as `pt-BR`. Never use a region alone.
- Add one `hreflang="x-default"`.
- On custom pages, add the links yourself: `getAbsoluteLocaleUrl()` for each locale, plus `x-default`.
- `<EmDashHead>` emits `hreflang` only for content entries.
- Emit `hreflang` from `<head>` only. Do not pass `i18n` in the `sitemap()` options.
- Leave the EmDash collection sitemaps as they are, because they add `xhtml:link` alternates.

### Set the page language

- Set `<html lang={Astro.currentLocale ?? "en"}>` in the base layout.
- Do not hard-code `lang="en"`.
- Put `lang` on the element of text in another language. Use a valid BCP 47 tag. See [MDN](STACK.md#mdn).

## Translate EmDash content

### Turn on EmDash translation

- Use the same Astro `i18n` block to turn on translation in [EmDash](STACK.md#emdash). Without it, EmDash is single-language.
- Pass `locale` to `getEmDashCollection(collection, { locale })`, `getEmDashEntry(collection, slug, { locale })`, `getMenu(name, { locale })`, and `getTaxonomyTerms(taxonomy, { locale })`. Otherwise they use the default.
- Use `entry.data.slug`, without a locale prefix, for route segments.
- Use `entry.data.id` for `getTranslations()` and `getEntryTerms()`.
- The fallback chain (requested, `fallback`, default) applies to single-entry queries only. List queries return the requested locale only.
- Keep the same slug across translations that rely on the fallback chain.
- For different slugs, use `getTranslations(collection, id)`.
- Filter out drafts and scheduled entries before you show a public switcher.
- Put `<EmDashHead>` in the base layout.
- `getHreflangAlternates(collection, id, { siteUrl })` needs an absolute `siteUrl`. Otherwise it returns `[]`.
- Set `translatable: false` on fields that are identical in all locales, such as price or image. EmDash copies them on publish.
- Create translations with the PolyStella panel, the admin **Translate** action, or `emdash content create <collection> --locale <code> --translation-of <id> --draft`.
- For EmDash collections, use its locale-aware `/sitemap-{collection}.xml`.
- Do not translate the EmDash admin UI in site code. See [Translating EmDash](https://docs.emdashcms.com/contributing/translating/).

### Translate content with PolyStella

- To translate EmDash content with AI, use the package `@cloudflare/polystella-emdash` ([PolyStella](STACK.md#polystella)).
- Register it as a native plugin: `emdash({ plugins: [polystellaEmdash(options)] })`. The peers come with EmDash.
- Do not use `@cloudflare/polystella-astro`. It translates repository files at build time and has its own routes. Use EmDash content and Astro i18n routing.
- Do not use `polystellaEmdashAstro()`, which adds `Astro.locals.t`, `lhref`, and catalog overrides. Use Paraglide JS for UI strings.
- Set `catalogs`. It is required.
- Give `catalogs` the `defaultLocale` and one `locales` entry for each Astro `locales` code.
- Write each entry as `{ dictionary: {}, filePath: "polystella/<locale>.json" }`. The file does not need to exist.
- Build `catalogs` from the shared `locales` array. See [Share one set of locales](#share-one-set-of-locales).
- Leave the **Catalog** tab and the overrides unused.
- Set `provider: { kind: "workers-ai-binding", binding: "AI" }`.
- Add `"ai": { "binding": "AI" }` to `wrangler.jsonc`. See [DEPLOY](DEPLOY.md).
- Workers AI bills the account also in `astro dev`.
- Set `models.allowed` to a non-empty list of Workers AI text models, such as `@cf/zai-org/glm-4.7-flash`.
- Set `models.defaults.default` to a model in `allowed`.
- An administrator enables collections and fields in **PolyStella** > **Collections**. Nothing is on by default.
- PolyStella translates `string`, `text`, and Portable Text fields.
- The panel creates or updates a translation draft (`translationOf`) and never publishes. Review the draft, then publish.
- To use a glossary, set `glossaryDefaults: await loadGlossaryDefaults({ locales, file: "./src/i18n/glossary/{locale}.yaml", projectRoot: new URL(".", import.meta.url) })`.
- Import `loadGlossaryDefaults` from `@cloudflare/polystella-emdash/config`.

## Translate UI strings

### Set up Paraglide JS

- Use [Paraglide JS](STACK.md#paraglide-js) for the site. The app shares one catalog with it. See [SAAS](SAAS.md).
- Do not use PolyStella for UI strings. Do not use `Astro.locals.t`.
- Do not run `polystella translate-ui` on `messages/`. It protects only `{{name}}`, not `{name}`, and it translates `$schema`.
- Write `messages/{locale}.json` with flat keys and `{name}` placeholders.
- Call `m.key({ name })` from `src/paraglide/messages.js`.
- In `project.inlang/settings.json`, set `baseLocale` and `locales` equal to `defaultLocale` and `locales` in `astro.config`.
- Add `paraglideVitePlugin({ project: "./project.inlang", outdir: "./src/paraglide", emitTsDeclarations: true, strategy: ["url", "globalVariable", "baseLocale"] })` to `vite.plugins`.
- Put `globalVariable` before `baseLocale`, because prerendered pages need it.
- Inside `paraglideMiddleware()`, `getLocale()` reads AsyncLocalStorage first.
- Do not set `disableAsyncLocalStorage`. Workers support `node:async_hooks`, and Node.js APIs are on by default with `compatibility_date` `2026-08-04` or later. See [ARCH](ARCH.md).
- Do not use a server `overwriteGetLocale()` without per-request locale storage.

### Write the middleware

- In `src/middleware.ts`, branch on `context.isPrerendered`.
- For on-demand pages, call `paraglideMiddleware(context.request, () => next())` from `src/paraglide/server.js`.
- Never pass the `request` of the callback to `next()`. It has the prefix stripped, so Astro rewrites `/de/about` to `/about` and skips `src/pages/de/`.
- Never call `setLocale()` on on-demand pages. It is a shared global across concurrent requests in an isolate, so the locale can be wrong. See [ARCH](ARCH.md).
- For prerendered pages, do not call `paraglideMiddleware()`.
- Call `setLocale(assertIsLocale(context.currentLocale ?? baseLocale))` from `src/paraglide/runtime.js`, then `return next()`.

## Share one set of locales

- Keep one text in one place.
- Put text that editors change (entries, menus, taxonomies) in EmDash, and translate it with PolyStella.
- Put text in code (`.astro`, islands, form errors, emails) in `messages/`.
- Do not copy an EmDash text into `messages/`. Do not put a UI string in a collection.
- Define one `locales` array and one `defaultLocale` constant in `astro.config.mjs`.
- Feed them to `i18n`, to PolyStella `catalogs` (`Object.fromEntries(locales.map(...))`), and to `loadGlossaryDefaults({ locales })`.
- Copy the same codes into `project.inlang/settings.json`, because JSON cannot import.
- Keep one glossary: `src/i18n/glossary/{locale}.yaml`, with PolyStella `doNotTranslate` and `preferredTranslations`.
- Use the same terms when you translate `messages/`.
- Translate `messages/{locale}.json` by hand and keep every `{name}` unchanged. [polystella#66](https://github.com/cloudflare/polystella/issues/66) would allow `translate-ui`.
- Add the dev package `@inlang/cli`.
- Add `inlang check --project ./project.inlang` to the `check` script.
- The check fails on missing translations and on missing or unknown variables.
- If messages are used only in `.astro` files, the check skips the unused-message check.
- Write source messages in English. See [WRITING](WRITING.md).
- Translation files are the only non-English files.

## Format dates and numbers

- Format dates with `new Intl.DateTimeFormat(locale, { dateStyle, timeZone })`. See [MDN](STACK.md#mdn) `Intl`. Do not build date strings by hand.
- Always pass `locale` (`Astro.currentLocale`) and `timeZone`.
- Format ranges with `formatRange()`.
- Format numbers with `new Intl.NumberFormat(locale, options)`. Do not use `toFixed()` or manual separators.
- With `style: "currency"`, set `currency`. With `style: "unit"`, set `unit`. Otherwise it throws a `TypeError`.
- Use `notation: "compact"` for values such as `1.2M`.

## Add a right-to-left language

- Add an RTL locale only when the task needs it.
- Set `<html lang={Astro.currentLocale ?? "en"} dir={getTextDirection()}>`, with `getTextDirection()` from `src/paraglide/runtime.js`.
- Put `dir` on `<html>`. Do not use CSS `direction`.
- Use `dir="auto"` on user text of unknown direction, and `<bdi>` inline.
- Use [Tailwind CSS](STACK.md#tailwind-css) logical utilities (`ps-*`, `pe-*`, `ms-*`, `me-*`) for reading-direction spacing.
- Never use `pl-*`, `pr-*`, `ml-*`, or `mr-*` for it.
- Use the `rtl:` variant for other direction styles.
